# Summary

The json experience writes `$schema` with the URI of `schemas/json_experience_v3.schema.json`, a JSON Schema (draft 2020-12) describing the document. The schema ships with the package and is validated against documents produced by the experience in the tests.

# Motivation

The integer `schema_version` signaled breaking changes but did not describe the document's structure, so consumers had to infer it from the README example. A published schema lets consumers validate documents and generate bindings, and a per-version schema file keeps older documents pointing at the schema they were written against.

# Changes

- Added `src/RepoAuditorWeb/schemas/json_experience_v3.schema.json`, whose `$id` matches the `$schema` value written to the document.
- `json_experience.py` increments `_SCHEMA_VERSION` to 3 and derives `_SCHEMA_URI` from it; the document emits `$schema` instead of `schema_version`.
- Added `TestSchema` in `tests/json_experience_test.py`, which checks the schema and validates documents for results, a repository error, and a top-level error.
- Added `jsonschema` as a development dependency.
- Updated `README.md` and existing tests for the new field.

# Compatibility

- Breaking for consumers of the json document: `schema_version` was removed. The version is now encoded in the `$schema` URI (`json_experience_v3.schema.json`).
